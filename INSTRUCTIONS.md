Project Instructions Overview
Follow these guidelines consistently across code, documentation, and processes.
1. Core Principles & Best Practices

Code Quality — Write clean, readable, modular code. Use strict TypeScript, ESLint + Prettier, proper comments/JSDoc for complex logic.
Performance First — Leverage Next.js features: Server Components, Server Actions, Partial Prerendering, caching/revalidation. Keep bundles lean (Drizzle helps here).
Maintainability — Modular folder structure, single-responsibility files, separation of concerns (UI vs logic vs data).
Accessibility & DX — shadcn/ui components are accessible by default → extend thoughtfully. Prioritize intuitive UX (e.g., modal previews, Cmd+K search later).
Security — Clerk for auth/roles → enforce in middleware + actions. Validate inputs (Zod). Never expose raw DB errors.
Documentation — Every feature gets clear explanations. Use MDX in /docs for rich examples.

3. Key Development Workflows

Adding a New Component/Template/Starter
Define schema in db/schema.ts (e.g., add fields like difficulty, techStack: string[]).
Run npx drizzle-kit push:pg (dev) or generate/apply migrations.
Create Server Action in actions/components/ for CRUD.
Build admin form/page in /app/(admin)/components/.
Add public view in /app/(public)/components/.
Use shadcn/ui primitives → compose previews with live code blocks (shiki for highlighting).
Add copy-to-clipboard button (use navigator.clipboard + toast feedback).

Authentication & Authorization
Use Clerk middleware to protect /admin/* → check user.publicMetadata.role === 'admin'.
In Server Actions: const { userId } = auth(); if (!userId) throw new Error('Unauthorized');
For user management: CRUD invites, pending/accepted status via Clerk + custom DB table if needed.

Data Fetching & Mutations
Reads → Direct in async Server Components (e.g., gallery lists).
Writes → Server Actions with Zod validation, revalidatePath('/components'), optimistic UI where possible (useActionState).
Use Drizzle prepared statements implicitly; add indexes on published, tags (jsonb GIN).

Performance Optimizations
Enable Partial Prerendering on gallery pages.
Cache stable queries (Next.js fetch or Drizzle caching helpers if needed).
Monitor with Vercel Speed Insights + Analytics.

Testing & Quality
Unit: Vitest for utils/actions.
E2E: Playwright for admin flows, gallery interactions.
Lint/format on commit (Husky + lint-staged).
